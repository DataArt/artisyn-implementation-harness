**RF-037 — developer live-review round.** The developer looked at the rendered graph (dev server, two screenshots) and found three problems the first pass missed:

1. **Ring overflow/clumping.** Read `node_modules/cytoscape/src/extensions/layout/concentric.mjs`'s own source: `equidistant: true` rewrites every level's radius to advance by `rDeltaMax`, the single largest per-level radius delta across all rings. The outermost `Other`/`AppReadme` ring (holding most of ~115 docs) needs a huge radius to avoid node overlap at that density, so `equidistant` imposed that same huge gap on every ring, overflowing the fit bounding box — exactly the clipping the screenshot showed, and exactly what cytoscape's own defaults comment warns about (`equidistant: false, // ... may cause bounding box overflow`). Fix: dropped `equidistant` entirely (default `false`), relying on the layout's own per-level minimum gap (`maxNodeSize + minNodeSpacing`, which holds regardless of per-ring node count) instead; bumped `minNodeSpacing` 20→32 for more breathing room between same-ring nodes now that rings aren't artificially blown out.
2. **Illegible zoomed-in labels.** The base node style had a full-opacity 2px `text-outline` colored to match each tier's node fill — on a colored node this reads as the label smearing into the node (confirmed directly in the developer's zoomed screenshot: `Web Container`'s label was nearly unreadable against its own blue outline). Replaced `text-outline-*` with a `text-background-*` plate (`roundrectangle`, opacity 0.88). Investigated whether this site supports dark mode (it does — VitePress's default theme, confirmed via `config.ts`/`custom.css`/`GiscusComments.vue`'s theme-aware patterns) before hardcoding a color: a hardcoded white plate would've been wrong in dark mode, and a hardcoded near-black label text would go illegible against a dark-mode-aware plate — so both the plate and the label text color now read this site's own `--vp-c-bg-soft`/`--vp-c-text-1` CSS custom properties live via `getComputedStyle`, with a `watch(isDark, () => cy?.style(...))` restyle when the theme toggles (no remount needed, since VitePress just flips a class on `<html>`).
3. **No way to reach a doc's page from a node.** New `docUrl.ts`: `path` (repo-root-relative, e.g. `docs/Engineering Guide/01 Conventions.md`) → the site's actual route. This site's `srcDir` is `docs/` and does not set `cleanUrls` (confirmed against `apps/docs-web/.vitepress/dist/`'s real build output — pages keep `.html`, and `README.md` stays `README.html`, not rewritten to `index.html`), so the mapping is: strip the `docs/` prefix, swap `.md`→`.html`, percent-encode each segment (paths contain spaces), prefix with `withBase()`. Returns `null` for any path outside `docs/` (e.g. `AppReadme`-tier docs like `apps/infra/README.md`, which have no VitePress route at all) — callers never produce a broken link for those. Wired to a `cy.on('tap', 'node', ...)` → `window.open(url, '_blank', 'noopener')`, a pointer-cursor affordance on hover gated on a resolvable URL (an `AppReadme` node never looks clickable), and the fallback table's title cell (same `docUrl`, used by both).

Both rounds delegated to `@web`; orchestrator independently re-read every touched file end to end and re-ran `yarn nx run site:typecheck`/`site:lint`/`site:build` after each (all clean). **Not independently verified visually** — the Chrome extension wasn't connected this session, so the orchestrator could not open the rendered page itself; asked the developer to confirm at `http://localhost:5174` (dev server left running for this).

# DESIGN-20261115-V98J: Log Hub Session Telemetry Integration — Design

_Internal structure of the `log-hub` container introduced in `Architecture.md`. Rationale and rejected alternatives are in `design/02 Evaluate - Server topology.md` and `design/02 Evaluate - Repo integration footprint and canonical isolation.md`._

## Components (within `apps/log-hub/`)

| Component                                                            | Responsibility                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Contract                                                                                                                                             |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |

| `scripts/install-hook.mjs` (targets: `install-hook`, `upgrade-hook`) | Prints the disclosure text and requires an explicit confirmation; fetches the hook installer tarball from the contributor's own running local server (`http://127.0.0.1:5003/static/artisyn-hooks-installer.tgz`) via `yarn dlx` if viable, else a scoped `npx` call internal to this script only; runs it with `--server-url http://127.0.0.1:5003 --api-key <prompted>`; restores `.claude/settings.json` from the `.bak` the installer writes; runs `claude plugin marketplace add ./.artisyn/marketplace --scope local` and `claude plugin install log-hub-hooks@<hash> --scope local`; sets `otelTraces`/cost-advisor off in `.artisyn/config/log-hub.json`. | Aborts if `.claude/settings.json` differs from its pre-run content after the restore step (fails closed instead of silently leaving committed keys). |

## Failure modes

- Checksum mismatch at `serve`/`upgrade` aborts the script before `docker compose up`. No partial install.
- `install-hook` run against a server that is not up aborts with a clear message to run `log-hub:serve` first.
- Local-scope plugin registration not working (if the Decision 6 spike fails before the fallback ships) makes `install-hook` fall back to the committed-marketplace layout; `verify`'s allowed-key set changes accordingly. This is a build-time switch in the script, not a runtime decision.
- `verify` failing in CI blocks the PR. The failure message names the exact assertion (settings keys, untracked paths, or canonical hash) so it is actionable without reading the script.

## Configuration and secrets

- `apps/log-hub/VERSION` — committed, plain text, the pinned release tag.
- `apps/log-hub/.local/.env` — gitignored; `POSTGRES_PASSWORD` and `SESSION_SECRET` are generated by upstream `install.sh` on first run and never regenerated.
- `.artisyn/config/log-hub.local.json` — gitignored, always, under both layouts; holds `apiKey`, `serverUrl` (loopback by default), `otelReceiverPort`. Never committed.
- `.artisyn/config/log-hub.json` — the installer's own default config (`otelTraces`/cost-advisor off). Gitignored under the primary layout. Committed only if the Decision 6 fallback ships, alongside `.artisyn/marketplace/`.
- `.claude/settings.json`'s `permissions.deny` list carries two entries for this design: `Read(./apps/log-hub/.local/**)` and `Read(./.artisyn/**)`, so a Claude Code session never uploads either secret-bearing path in a transcript.
- No secret is ever a target input or CLI argument that would appear in shell history beyond the API key prompt at `install-hook` time.

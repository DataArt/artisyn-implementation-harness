## Recommendation

**Recommend Option B — build-time script, implemented as the developer's proposed single reusable `.mjs` module (class/interface with `search`, `query`, `index`/`reindex`, `build` methods) — invoked automatically by the VitePress build _and_ directly callable by an agent/CLI on demand.**

This resolves the hybrid-shape question raised in the matrix above: it is not a sixth infra-footprint tier — it is Option B with a richer implementation shape than Research's literal "VitePress build plugin or pre-build CI step" description assumed. The infra-footprint test is whether anything _standing_ gets added — a server, schedule, daemon, webhook listener. An agent invoking the same script ad hoc (during bootstrap/launch, or whenever a lifecycle step needs to read/write the graph) is a transient, one-off process execution — identical in operational character to Option A's "developer/agent runs script locally, on demand," just using the same artifact CI also calls. Nothing about agent invocation introduces a long-running process. Conclusion: same infra tier as B, not a new one.

Why this satisfies the ECs: minimal/no new infra (no new deployable, no schedule, no standing process — the script executes transiently whether called by CI or an agent); deterministic regeneration (the build-triggered call guarantees the published/IDE graph can never silently drift, closing A's and C's main gap, while agent-callable `index`/`build` methods give the same deterministic rebuild on demand mid-lifecycle); no measured gap for standing infra (D/E remain disqualified, nothing standing introduced); reliably invokable by both agents and CI (the one criterion none of A/B/C cleanly satisfied alone — this hybrid shape closes that gap by being the one artifact both paths call).

Why D/E remain disqualified (restated, not re-litigated): no stated use case requires live/interactive queries, and no measured gap exists per Roadmap §5.9. Nothing in the hybrid-shape vision reopens D/E — it's explicitly transient execution, not a standing service.

Falsifiability: (1) a measured graph-freshness gap where build-cadence staleness breaks an actual lifecycle step would reopen Option D or tighten C's enforcement; (2) doc-tree scan time at build becoming a measured CI bottleneck would push toward incremental/cached scanning inside the same script, not a different infra tier.

# Non-Functional Requirements

| ID    | Category   | Requirement                                                                                                                                                                                                                                                                                                                                                                                      | Priority |
| ----- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- |
| NFR-1 | Security   | All site routes must be protected by basic auth — unauthenticated requests receive `401 WWW-Authenticate`                                                                                                                                                                                                                                                                                        | P1       |
| NFR-2 | Security   | Credentials must not be hardcoded in source — loaded from Secrets Manager at cold-start runtime via `GetSecretValue`                                                                                                                                                                                                                                                                             | P1       |
| NFR-3 | Operations | Region is deployment configuration — never hardcoded in source or documentation                                                                                                                                                                                                                                                                                                                  | P1       |
| NFR-4 | Operations | All infrastructure defined as code (AWS CDK) — no manual provisioning                                                                                                                                                                                                                                                                                                                            | P1       |
| NFR-5 | Operations | VitePress build must fail on any dead internal link — `ignoreDeadLinks` must not be set in `config.ts`                                                                                                                                                                                                                                                                                           | P1       |
| NFR-6 | Security   | Comments (giscus): posting is gated by GitHub repository permission on the repo configured via `GITHUB_ORG`/`GITHUB_REPO` (verified — accounts without access cannot post); reading is not — any visitor who reaches the page (i.e. anyone with the site's basic-auth password) can read all comments, since giscus.app's backend fetches via the App's own installation token, not the viewer's | P2       |

## Constraints

- No cost ceiling defined for this engagement
- Small team, internal access only (~10 users)
- Fixed-duration engagement scope

# Web Portal — Overview

Implementation detail for the Web Portal container: a composition-only Nx project at `apps/web-portal` with no application source. Mirrors `docs/Target Architecture (HLD)/v1/Containers/Web Portal.md`.

- `apps/web-portal/project.json` — `sourceRoot` is empty: this project has no source of its own. `implicitDependencies: ["web-explorer", "web-docs"]` is the Nx project-graph edge — the thing `nx affected` reads to mark `web-portal` affected whenever either sibling changes. The `build` target's `dependsOn: ["web-explorer:build", "web-docs:build"]` is a separate concern, task ordering: it tells Nx's task runner to run both builds before this one, regardless of the graph edge. Confirmed via architect review during Implement that these are two distinct mechanisms, not duplicate configuration for the same thing.
- `scripts/ci/portal-assemble.ts` — copies Web Explorer's built `dist/` to `apps/web-portal/dist/` (the artifact root) and Web Docs's built `.vitepress/dist/` to `apps/web-portal/dist/docs/`. After both copies, it asserts `apps/web-portal/dist/index.html` and `apps/web-portal/dist/docs/index.html` both exist via `fs.existsSync`, throwing a descriptive error naming whichever is missing if not — no silent partial deploy.

## Integration patterns

- `yarn nx run web-portal:build` runs the two dependency builds first (visible as separate Nx tasks in the output), then `portal-assemble.ts`, producing `apps/web-portal/dist/` with `index.html` at its root and a `docs/` subdirectory with its own `index.html`.
- `.github/workflows/cd.yml`'s `actions/upload-pages-artifact` step's `path` is `apps/web-portal/dist` — this composed tree, not either individual app's own `dist`. `actions/configure-pages`'s auto-detection runs against this merged, multi-framework tree.
- `yarn nx show project web-portal --json` lists `web-explorer` and `web-docs` under `implicitDependencies` — the live proof `nx affected` correctly marks `web-portal` affected when either sibling changes.

## Key decisions

- `implicitDependencies` (graph edge) and `build.dependsOn` (task ordering) are both declared, deliberately not collapsed into one — they answer different questions (`nx affected`'s change-detection vs. the task runner's execution order) even though in this project's case they name the same two projects.
- The assemble script fails loudly (throws, non-zero exit) rather than warn-and-continue on a missing entry point — a partial deploy to GitHub Pages is worse than a failed CI build.
- `apps/web-portal/dist/` is the sole artifact `cd.yml` uploads; no other build output is uploaded directly to GitHub Pages.

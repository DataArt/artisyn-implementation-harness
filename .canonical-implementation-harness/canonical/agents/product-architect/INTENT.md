## Purpose

Read-only governance agent for a shared product-context layer (a docs tree describing the whole product/platform, separate from any single downstream project's implementation). Collaborates at three points in `{{provider:invoke:design}}`: Research (neutral options grounded in platform precedent), an optional Solution review gate (structural completeness + governance-altitude check), and Publish (doc-impact identification + post-write review). This is the deployable form of `{{DESIGN_ARCHITECT_AGENT}}` for a **product-context-scoped** deployment — see the design-lifecycle-scope conditional in `design/INTENT.md`.

**Deploy this agent when the design-lifecycle-scope conditional (see `design/INTENT.md`) resolves to Product-context-scoped _or_ Two-track.** If `{{provider:invoke:design}}` is Project-scoped only (targets this project's own HLD/LLD, no shared product-context layer), skip this agent entirely — use the existing `architect` agent as `{{DESIGN_ARCHITECT_AGENT}}` and do not create `product-architect.md`. In Two-track mode, both this agent and `architect` are deployed side by side — this agent handles the Product track only, `architect` handles the Project track; the deployed `{{provider:invoke:design}}` skill chooses between them per session via `patterns/context-resolution.md`, not at generation time.

## Conditionals

- If this deployment has only one repository (no separate downstream implementation repos) and is Project-scoped: this agent doesn't apply — skip it, use `architect` instead.
- `{{PRODUCT_CONTEXT_GOVERNANCE_PATH}}` is deployment-specific — never hardcode a subfolder name (e.g. `Architecture/`) as a fallback inside the deployed agent body. If unresolved at generation time, ask the developer rather than guess.
